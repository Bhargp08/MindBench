# ETL: Google Drive to SQLite (MB-14)

Code: `etl/mindbench_etl/` (`download.py`, `validate.py`, `schema.sql`, `db.py`, `load.py`, `cli.py`). Tests: `etl/tests/` (synthetic fixtures only, generated by `etl/tests/fixtures/generate_fixtures.py`; no real data).

## Flow (runs locally on Bharg's machine; CI never sees real data)
```
DataPipe -> Google Drive folder (private) --download--> data/raw/*.json --validate+load--> data/mindbench.sqlite
```
`data/` is gitignored. Commands (from `etl/`):
```bash
uv run python -m mindbench_etl download --dest ../data/raw   # needs the two environment variables below
uv run python -m mindbench_etl load --raw ../data/raw --db ../data/mindbench.sqlite
```

## Credentials (environment variables only; never printed, stored or committed)
- `MINDBENCH_DRIVE_FOLDER_ID`: ID of the Drive folder DataPipe writes into.
- `GOOGLE_APPLICATION_CREDENTIALS`: path to a **service-account** key file (read-only scope `drive.readonly`).

**One-time setup (external actions, Bharg):** create a Google Cloud service account, enable the Drive API for it, share the DataPipe folder with the service account's email as **Viewer**, and keep the key file outside the repo. Error messages name the variables but never print their values.

**Drive API facts checked against Google's docs (Nov 18, 2026):** `files.list` is `GET https://www.googleapis.com/drive/v3/files` with `q` (`'FOLDER' in parents and trashed = false`), `pageSize` up to 1000, `pageToken`/`nextPageToken`, `supportsAllDrives`/`includeItemsFromAllDrives`; downloads use `files.get?alt=media` with a content-read scope; `md5Checksum` is available for files with binary content and is used to skip unchanged files. **Not tested live:** no credentials were available, so the real Drive calls are covered only by tests against a fake session. Try it first on a throwaway folder.

## What the downloader skips
Folders and non-`.json` files; `*.partial.json` files (DataPipe's recovery file for abandoned sessions); file names that could write outside the destination; files whose MD5 already matches the local copy. Files are written atomically and their MD5 is checked.

## Validation (`validate.py`)
Input is the JSON array of jsPsych rows the experiment uploads (or the dev mock object with a `trials` array). Every row must carry the participant code (8 characters, no 0/1/I/L/O), session number, questionnaire (sleep hours 0-16, KSS integer 1-9, times HH:MM, caffeine boolean, device), session metadata and task order (a permutation of the 5 tasks), and all rows of a file must agree. `trial_index` must be strictly increasing. Each task tag has its own JSON schema (staircase, yes/no, threshold, Posner, Stroop, 2-back, recall words, recall, recall summary, setup, timing, ...); unknown task names are rejected. Errors say which row, trial_index, task and field. A file named like `<code>_session<N>.json` must match its content; other names (for example DataPipe's random fallback name) are accepted.

## Schema (`schema.sql`)
`participants`, `sessions` (with `is_pilot`, `excluded_reason`, session metadata, task order, instructed viewing distance, refresh rate), `questionnaire`, `trials` (every row: `task`, `practice`, `rt`, `response`, `correct`, and the full row in `data_json`). Foreign keys are enforced; each trial key is `(participant_code, session_number, trial_index)`.

## Loading (`load.py`)
- **Idempotent:** re-loading a file upserts on the keys; counts do not change; rows missing from a newer upload are removed.
- **Atomic:** a file is validated before any write, and each file loads in one transaction, so a bad file or a database error part-way leaves nothing behind.
- **Pilot flag:** `is_pilot = 1` for sessions 1-10, `0` from session 11 (`--pilot-sessions` changes the cut).
- **`excluded_reason` is `NULL` at load** and is never overwritten by a reload. The preregistered exclusion rules are applied in MB-15.
- **Practice rows** keep their `practice = 1` tag; rows without a tag (fixation, cues) have `practice = NULL`. **MB-15 must exclude practice rows** and use only rows with `practice = 0`.

## Known gaps
- Live Google Drive download untested (see above).
- Sessions that stopped part-way are not flagged here; incompleteness is an MB-15 exclusion rule.
- Free-text recall responses are stored in `data_json`; they are dropped before any public release (MB-24).
